Act as an Operations Manager at [Company Name] operating under [UK / US] standards. Create a Standard Operating Procedure (SOP) for the following process:

[Describe the process here]

Structure the SOP as follows:
1. Purpose and scope
2. Roles and responsibilities (who does what)
3. Step-by-step procedure (numbered, action-oriented language)
4. Key controls and compliance checkpoints
5. Document owner, version number and review date

Tone: clear, direct and imperative. Use "must" for mandatory steps. Use "should" for best practice recommendations. Flag any step that requires sign-off or approval with [REQUIRES AUTHORISATION].

Act as an Operations Manager at [Company Name]. Draft a formal incident report for the following event:

[Describe the incident: what happened, when, where, who was involved]

Structure the report as follows:
1. Incident summary (one paragraph — factual, no opinions)
2. Timeline of events (chronological, with timestamps if available)
3. Immediate actions taken
4. Root cause analysis (apply 5 Whys methodology)
5. Corrective actions required (table: Action | Owner | Deadline | Status)
6. Escalation required: Yes / No — if yes, flag with [ESCALATE TO: name/role]

Tone: factual and neutral. Do not assign blame. Focus on process failure, not individual error. Flag any regulatory or compliance implications with [COMPLIANCE REVIEW REQUIRED].

The 5 Whys methodology asks "why" repeatedly to trace an issue back to its underlying cause, not just its symptom.

Act as an Operations Director at [Company Name]. Produce a KPI summary report for [period: week / month / quarter] for presentation to [audience: leadership team / board / department heads].

Data to include:
[Paste your KPI data here — numbers, percentages, targets vs actuals]

Structure the report as follows:
1. Executive summary (3 sentences maximum — headline performance)
2. KPI dashboard (table: Metric | Target | Actual | Variance | RAG Status)
3. Key wins this period (bullet points)
4. Issues and risks (bullet points — each with an owner and proposed action)
5. Priorities for next period

Tone: concise and data-led. Use RAG (Red / Amber / Green) status for each KPI. Flag any metric more than 10% below target with [AT RISK — ACTION REQUIRED].

RAG status turns a wall of numbers into a scannable dashboard your leadership team can act on in a glance.

Frequently asked questions

Frequently asked questions
What makes an Operations prompt different from a generic prompt?
Three things: process specificity, accountability language, and compliance awareness. Operations documents follow defined formats, must name an owner and a deadline for every action, and often feed into audit or compliance processes — so the prompt has to build all three in from the start.
Can I reuse these templates across different Operations tasks?
Yes. Each template follows the same Role, Context, Task, Format structure. Swap the bracketed placeholders for your company name, jurisdiction, and specifics, and the underlying structure keeps producing consistent, audit-ready output.
How do I make Claude match my company's document standards?
Add your standard format directly into the prompt — font, heading style, version control requirements. For example: "Our standard document format uses Arial 11pt with page numbering. All documents must include version control in the footer." Claude applies it automatically from the first draft.
Do I need to review Claude's output before using it?
Always. Every SOP, incident report, or supplier communication produced with these templates is a first draft. It must be reviewed and approved by the relevant process owner before it is published, distributed, or acted upon — Claude drafts, you remain the accountable owner.
What is the RAG status used in the KPI Summary template?
RAG stands for Red, Amber, Green — a traffic-light system for metric performance. The KPI Summary template asks Claude to apply a RAG status to every metric and flag anything more than 10% below target as at risk.
