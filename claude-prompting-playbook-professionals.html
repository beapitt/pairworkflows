Step-by-step workflow

Apply the advanced prompting playbook — 5 steps
1

Assign a specific, strategic role

Not "an assistant" — a Senior FinTech Risk Auditor, a B2B Growth Architect. A specific persona shifts Claude's attention toward the terminology and standards that role actually uses.

2

Wrap messy source text in XML tags

Use tags like <context> or <transcript> around anything you paste in. This tells Claude exactly where the data stops and your instructions begin.

3

State what Claude must not do

Models default to generating assertions, not omissions. List banned words, banned topics, and banned tones explicitly — don't assume Claude will infer them.

4

Define the exact output shape

For anything feeding into another system, specify JSON, a markdown table, or CSV — and tell Claude to skip the conversational preamble entirely.

5

Move recurring rules into a system prompt

For anything you do weekly, set a system prompt inside a Claude Project. Brand voice, security limits, and format rules then apply automatically to every conversation in that Project.

Chain complex tasks, don't cram them: Forcing Claude to execute several complex operations in a single prompt degrades quality. Break a heavy assignment into sequential steps — extract, then build — across separate turns instead.

Frequently asked questions

Frequently asked questions
Why does assigning Claude a role change the quality of its output?
Without an assigned role, Claude draws from a generalized average baseline, producing generic business prose. Forcing Claude into a specific persona — a Senior Risk Auditor rather than just "an assistant" — shifts its attention toward the terminology, risk framing, and presentation standards that role actually uses.
What are XML tags used for in a Claude prompt?
XML tags like <context> or <source_material> separate raw user data from your core instructions. Wrapping messy pasted content in tags tells Claude exactly where background noise stops and instructions begin, which eliminates context contamination and prevents Claude from mistaking pasted text for a command.
Why do I need negative constraints if I already described the task clearly?
Language models default to generating assertions, not omissions. Describing the task tells Claude what to include; it does not tell Claude what to avoid. Explicit negative constraints — banned words, banned tones, banned topics — are the only reliable way to keep corporate boilerplate and off-brand phrasing out of the first draft.
What is prefilling and when should I use it?
Prefilling means writing the opening of Claude's response yourself, such as starting a code block with "```yaml". It skips conversational preambles like "Certainly, I'd be happy to help" and forces the reply to start exactly where you need it, which matters most for machine-readable output like JSON or YAML.
What is the difference between a user prompt and a system prompt?
A user prompt carries transient, task-specific instructions for a single conversation. A system prompt, set inside a Claude Project, sets permanent guardrails — brand voice, security limits, output format — that apply across every conversation in that Project and cannot be overridden by a single user message.
