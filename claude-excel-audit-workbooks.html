Section 01

Where Claude fits in when Excel gets complicated

Most Excel workbooks don't get built all at once—they grow over years. Formulas start referencing other formulas, new sheets keep getting added, old named ranges get forgotten, and eventually the original logic becomes pretty hard to follow. When you inherit one of these monsters—or even come back to something you built months ago—figuring it out can eat up hours.

Claude can't open Excel files directly, but it's fantastic at working with the information you pull out and share with it: formula text, sheet structures, lists of named ranges, and data samples. You describe what you're seeing, paste the relevant bits, and Claude helps you map out the logic, spot the risks, and understand what the workbook is really doing.

Excel 365 Formula bar — complex XLOOKUP formula with colour-coded arguments
The formula bar shows the full formula as you type. Each argument is colour-coded — Excel highlights the matching ranges in the sheet so you can see exactly what the formula is referencing.

Here's where Claude shines:

  • You paste a formula and it explains it in plain English, step by step
  • You describe the sheet structure and it helps you see likely dependencies and risks
  • You share a list of named ranges and it tells you which ones are active, orphaned, or might be broken
  • You paste error values and it diagnoses the most likely causes
  • You describe the workbook's purpose and it helps you document it properly
Excel 365 Sheet with data — formula visible in formula bar when cell is selected
Clicking any cell that contains a formula reveals it in the formula bar at the top. This is the starting point for your audit — select the cells that matter and copy the formulas to paste into Claude.

Note: Claude isn't a replacement for Excel's built-in auditing tools like Trace Precedents, Name Manager, or the Formula Auditor. It works best alongside them: you use Excel to surface the raw details, and Claude to make sense of them.

Here's a simple six-step rhythm you can use every time you need to get to grips with a complex workbook.

01

Map the structure first

Before you paste anything into Claude, take about five minutes in Excel to get a quick structural overview. Note how many sheets there are, what each one seems to contain, which sheets reference other sheets, and whether there are any hidden or very hidden sheets (you may need to check the VBA editor for those).

02

Extract the key formulas

Go to the most complex sheet. Hit Ctrl+` (grave accent) to toggle into formula view — all cells show their formulas instead of values. Spot the formulas that look most interconnected or hardest to understand. Copy the three to five that worry you most.

Excel 365 Show Formulae active — all cells display formulas instead of calculated values
Ctrl+` (grave accent) toggles formula view. Every cell that contains a formula now shows the formula itself — making it easy to spot which cells are calculated and which are raw data.
03

Open Name Manager

Go to Formulas → Name Manager. This lists every defined name in the workbook — its scope, its refers-to value, and whether it's still active. Copy the full list and paste it into Claude, noting which ones you can't trace to active use.

Excel 365 Name Manager panel — Formulas → Name Manager
Name Manager lists every named range in the workbook. Orphaned names — ones that refer to deleted ranges or old sheets — show up here and are a common source of errors in inherited workbooks.
04

Run a first Claude prompt

Paste your structural overview, the key formulas, and the named range list into Claude. Give it a clear brief: what the workbook is supposed to do and what you need to understand. Ask it to explain the formula logic and flag anything that looks fragile, circular, or potentially broken.

Excel 365 XLOOKUP tooltip — Excel explains function arguments as you type
As you type a formula, Excel shows a tooltip with each argument. Copy this formula text — including all the arguments — and paste it into Claude. Claude will explain exactly what each part does and flag any risks.
05

Work through the audit iteratively

Claude's first response will give you a solid map and some initial flags. Use that to go back into Excel, check specific cells, and then return to Claude with follow-up questions. The audit turns into a helpful back-and-forth conversation rather than a single big query.

06

Document as you go

Ask Claude to create plain-English summaries of what each key formula does — perfect for a documentation sheet. Paste these back into Excel in a new sheet called DOCUMENTATION or as comments on the relevant formulas.

Excel 365 Formulas ribbon — Name Manager and Show Formulae buttons highlighted
The Formulas tab is your audit command centre. Name Manager and Show Formulae are the two buttons you'll use most — both are visible here in the ribbon.
Tip: Steps 4 and 5 repeat as many times as needed. Each round of Claude questions followed by Excel verification gets you closer to a complete picture of the workbook's logic.

Copy these prompts directly into Claude. Fill in the bracketed placeholders with your workbook's specifics.

Core audit prompt

Prompt — paste into Claude
I have an Excel workbook that [describe purpose — e.g. "tracks monthly revenue by region and feeds a summary dashboard"]. It has [X] sheets: [list sheet names]. I need to understand how it works before making changes. Here are the five formulas I find most complex: [paste formulas] Here is the full list from Name Manager: [paste defined names and refers-to values] Please: (1) explain what each formula is doing in plain English, (2) identify any dependencies between them, (3) flag anything that looks fragile, potentially broken, or that I should verify before editing.

Follow-up prompt for documentation

Prompt — paste into Claude
Based on your explanation above, write a plain-English documentation block for each formula — one paragraph per formula, suitable for a non-technical colleague who needs to maintain this workbook. Include: what the formula calculates, what inputs it depends on, and any known risks.

Pre-edit safety prompt

Prompt — paste into Claude
I want to change [describe the specific change — e.g. "add a new row to the data range on sheet INPUT"]. Based on what you know about this workbook's structure, what downstream effects should I check before and after making this change?
Audit checklist
Sheet inventory complete (including hidden sheets)
Key formulas identified using Ctrl+` and pasted into Claude
Named ranges reviewed in Name Manager and shared with Claude
Claude explanation reviewed and cross-checked in Excel
Circular references checked (Formulas → Error Checking → Circular References)
External links checked (Data → Queries & Connections → Edit Links)
Documentation sheet created or updated in the workbook
Pre-edit safety check done before any structural change
Important: Claude explains formulas based on what you paste. Always cross-check its output against the actual workbook before making changes or sharing documentation with colleagues.
