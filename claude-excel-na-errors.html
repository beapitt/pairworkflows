Diagnose and fix a #N/A error — 5 steps
1

Check the match argument

For VLOOKUP: is the fourth argument FALSE? If it's missing or TRUE, that's often the problem. For XLOOKUP, the default is already exact match, so this isn't the issue.

2

Compare the values in the formula bar

Click the cell with the lookup value, then a matching cell in the table. Look at both in the formula bar. If they look identical, the difference is invisible — a space or a type mismatch.

3

Run the manual test

Replace the cell reference with the value typed directly — change =VLOOKUP(A2,...) to =VLOOKUP("Smith",...). If the hardcoded version works, the problem is in the source data, not the formula.

4

Paste into Claude with the test result

Share the formula, a few sample rows of both the lookup value and the table, and whether the manual test worked. Claude identifies the mismatch and gives you the exact fix.

5

Apply the fix, then wrap in IFERROR

Usually TRIM() for spaces, VALUE() or TEXT() for type mismatches, or a FALSE fourth argument. Once confirmed correct, wrap the formula in IFERROR so future missing values show a dash instead of #N/A.

Many #N/A errors at once? Don't fix them one at a time. Paste a sample of the broken rows into Claude and ask for a single formula that handles all cases — including the IFERROR wrapper.

Frequently asked questions

Why does VLOOKUP return #N/A when the value exists?
VLOOKUP returns #N/A when it cannot find an exact match, even if the value appears to exist in the table. The most common causes are trailing spaces in the lookup value, a data type mismatch, or a missing FALSE argument in the fourth parameter.
How do I fix #N/A caused by trailing spaces?
Wrap your lookup value in the TRIM() function to remove leading and trailing spaces. For example, change =VLOOKUP(A2, D:F, 2, FALSE) to =VLOOKUP(TRIM(A2), D:F, 2, FALSE).
Does XLOOKUP still return #N/A errors?
Yes. XLOOKUP defaults to exact match, so the match argument is rarely the problem. It still returns #N/A when there is a data type mismatch or trailing spaces — the fix is the same, TRIM() or VALUE()/TEXT().
What is the fastest way to tell if #N/A is a formula problem or a data problem?
Replace the cell reference in your formula with the value typed directly. If the hardcoded version returns a result but the cell reference version returns #N/A, the problem is in the data, not the formula structure.
Should I wrap every lookup formula in IFERROR?
Only after you've confirmed the formula is correct. Wrapping a broken formula in IFERROR just hides the #N/A instead of fixing it — diagnose the real cause first, then add IFERROR for genuinely missing values.
