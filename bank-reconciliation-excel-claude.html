Rules:
- Match transactions by date and amount first. Use reference and description as secondary confirmation only.
- Dates are in DD/MM/YYYY format. Amounts use negative for outflows, positive for inflows.
- If a bank item matches a ledger item exactly (same date and amount), mark it "Matched".
- If a bank item matches a ledger item on date but the amounts differ, mark it "Partial" and show the difference.
- If a bank item has no corresponding ledger entry at all, mark it "Unmatched (Bank only)".
- If a ledger item has no corresponding bank entry, mark it "Unmatched (Ledger only)".
- Do NOT invent or force matches. Do NOT fabricate amounts. If something doesn't match, flag it.
- Do NOT assume timing differences resolve themselves — list every discrepancy.

Output:
1. A reconciliation table: Date | Bank Ref | Bank Amt | Ledger Amt | Difference | Status
2. A separate list of all unmatched items (bank-only and ledger-only)
3. A summary: Bank total, Ledger total, Total matched, Total unmatched, Net difference

Run a bank reconciliation with Claude — 5 steps

1

Export both datasets to Excel or CSV

Export your bank statement and general ledger cash account. Keep only individual transaction rows — delete summary rows, running balances, and any bank export headers that span multiple columns.

2

Align date formats and sign conventions

Both datasets must use the same date format (e.g. DD/MM/YYYY). Amounts must follow the same sign convention: negative for outflows, positive for inflows. Fix this in Excel before pasting into Claude.

3

Paste both datasets into the prompt

Use the Full Reconciliation prompt above. Paste your bank rows where indicated and your ledger rows below. Include column headers so Claude understands the structure.

4

Review every Partial and Unmatched item

Claude's output is a starting point, not a final answer. Every Partial match needs a root-cause investigation — timing difference, bank fee, or data entry error. Every Unmatched item on the bank side needs a journal entry or explanation.

5

Paste the reconciliation table into Excel

Claude formats the output as a tab-separated table ready to paste into Excel. Apply Ctrl+Shift+L to add filters, then sort by Status to group all Partial and Unmatched items at the top.

Tip: If all your items show Unmatched, the most likely cause is a date format mismatch. Tell Claude "dates in my bank export are MM/DD/YYYY and in my ledger they are DD/MM/YYYY" — it will normalise before matching.

Frequently asked questions

Can Claude read my Excel bank statement directly?
Claude cannot open .xlsx files natively in the free chat. Copy the relevant columns from Excel and paste them as plain text into the prompt. Claude Pro supports file uploads if you prefer to attach the file directly.
How does Claude match bank transactions to ledger entries?
Claude uses date and amount as the primary matching key. Reference numbers and descriptions are used as secondary confirmation. The prompt instructs Claude not to force matches — if two rows don't meet the matching criteria, they're flagged separately.
Will Claude invent matches that don't exist?
Not with this prompt. The guardrail line "Do NOT invent or force matches" is critical — it tells Claude to flag discrepancies rather than resolve them. Always verify the output against your source data before posting any adjusting entries.
Can I use this for multi-currency bank reconciliation?
Yes — use the Multi-currency prompt tab above. Add a Currency column to both datasets and specify the exchange rate in the prompt. Claude converts all amounts to your reporting currency before matching.
How often should I run this reconciliation?
Most finance teams reconcile monthly at minimum. Weekly reconciliation catches errors faster and makes month-end close significantly smoother. If you're building a broader close process, see the month-end close checklist workflow.
