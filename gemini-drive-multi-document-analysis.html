How to Analyse Multiple Documents at Once with Gemini AI

Reference 3–5 Google Drive files in a single Gemini prompt using @. Compare contract clauses, extract KPIs across quarterly reports, spot policy inconsistencies between regional handbooks — without opening each file manually.

Choose your scenario — copy the prompt: 
In the Gemini side panel, type this — replace @ references
with your actual file names:

Act as a contracts analyst. Compare these two supplier agreements:
- @[Supplier A contract filename]
- @[Supplier B contract filename]

Extract and compare the following clauses side by side:
1. Payment terms (days to pay, early payment discount if any)
2. Liability cap (amount and scope)
3. Termination notice period
4. Auto-renewal clause (yes/no, and notice window to cancel)
5. Governing law and jurisdiction

Format as a table:
Clause | Supplier A | Supplier B | Which is more favourable to us

Rules:
- Quote the exact clause language where it differs significantly.
- If a clause is missing from one contract, write [Not stated].
- Do NOT interpret ambiguous legal language — flag it as
  [Ambiguous — legal review recommended].
- Do NOT recommend which supplier to choose.

In the Google Docs side panel, type @ and start typing the filename to reference it. Works for up to 5 files per prompt.

In the Gemini side panel:

Act as a financial analyst. Extract the following KPIs from
each of these quarterly reports:
- @[Q1 report filename]
- @[Q2 report filename]
- @[Q3 report filename]
- @[Q4 report filename]

KPIs to extract:
- Revenue (total)
- Gross margin %
- Headcount (end of quarter)
- Customer count or ARR (whichever is reported)
- Any metric flagged as "at risk" or below target

Format as a table: KPI | Q1 | Q2 | Q3 | Q4 | Trend (↑ ↓ →)

Then below the table:
- List the 2–3 most significant quarter-on-quarter changes
- Flag any KPI where figures appear inconsistent across reports
  (e.g. headcount reported differently in two documents)

Rules:
- Use only figures explicitly stated in the reports.
- Write [Not reported] if a KPI does not appear in a quarter.
- Do NOT calculate or derive figures — only extract stated ones.

Most useful for board prep, investor updates, or annual review — spots inconsistencies that slip through when each report is read in isolation.

Run this before a policy audit, M&A integration, or any time you expand to a new region and need to align handbook versions.

Step-by-step workflow

Run a multi-document analysis with Gemini — 5 steps
1

Convert files to Google format before starting

Gemini reads Google Docs, Google Sheets, Google Slides, and PDFs natively. It cannot read .docx or .xlsx files — the @ reference will return nothing. Convert them first: open in Drive → File → Save as Google Docs/Sheets. Takes 10 seconds per file. Scanned PDFs without a text layer also produce poor results — run OCR first if needed.

2

Name files clearly before referencing them

When you type @ in the side panel, the dropdown shows filenames matching what you type. Descriptive names like Supplier A Contract v3 — June 2025 let you confirm you're referencing the right version before running the prompt. "Contract Final Final (2)" causes you to reference the wrong file and not notice.

3

Specify exactly what to extract — don't ask for a general comparison

A prompt that says "compare these two contracts" gets surface-level output. A prompt that says "compare payment terms, liability cap, termination notice period, and auto-renewal clause" gets clause-level output you can actually use. Name the specific fields, and tell Gemini to write [Not stated] when a field is missing rather than inferring it.

4

Keep batches to 3–5 files per prompt

Referencing too many files at once causes Gemini to spread its attention across all of them and miss detail in each. For large document sets — 10 contracts, 8 quarterly reports — work in batches of 3–5, then combine the outputs in a summary prompt that references your intermediate notes rather than all the source files again.

5

Click every citation link before using the output

Gemini shows citation markers next to extracted data — click each one to verify it matches the source document. For contract comparisons, verify every clause before the output goes to legal or procurement. For KPI extraction, verify every figure before it goes into a board deck. One wrong attribution in a contract comparison is expensive to fix.

For legal and financial documents: Gemini's output is a starting point for review, not a legal opinion. Never use an AI-generated contract comparison as the sole basis for a commercial decision. Always have qualified professionals review the source documents before signing or acting on any terms.

Frequently asked questions

How many documents can Gemini analyse at once?
3–5 files per prompt gives reliable results. Referencing more causes Gemini to surface-read each file and miss important detail in all of them. For large document sets, work in batches and combine outputs in a follow-up prompt.
Does Gemini create a merged document from multiple files?
No. Gemini generates analysis in the side panel or in your current document — it does not merge source files or create new documents automatically. The source files remain separate and unchanged.
Can Gemini find contradictions between documents?
Yes — one of the most useful applications. Ask Gemini to compare two policy versions or two contract drafts and flag contradictions. Be specific about which sections to compare, and always verify flagged contradictions against the source documents yourself before acting on them.
What file types work best for multi-document analysis?
Google Docs and Sheets give the most reliable results. PDFs also work. Files must be in Google format — convert .docx and .xlsx via File → Save as Google Docs/Sheets. Scanned PDFs without a text layer produce poor results.
How do I make sure Gemini reads the right document version?
Use specific, descriptive filenames that include version number and date — for example "Supplier Contract v3 — June 2025". When you type @ in the side panel, the dropdown shows matching filenames so you can confirm the right version before running the prompt.
